## Singleton Pattern

### Definition

Singleton ensures that a class has only one object throughout the
application and provides a way to access that object.


### Simple Explanation

Normally, a class can create multiple objects.

Singleton restricts the class to creating only ONE object.

One class → One object → Everyone uses the same object.


### Example: Game Settings

Suppose a game should have only one settings object:

class GameSettings {

private:

    GameSettings() {}

public:

    static GameSettings& getInstance() {

        static GameSettings settings;

        return settings;
    }

    void setVolume(int v) {
        cout << "Volume: " << v;
    }
};


### Usage

GameSettings::getInstance().setVolume(80);


### Why Use Singleton?

Without Singleton:

Game
 ├── Settings object 1
 ├── Settings object 2
 └── Settings object 3

With Singleton:

Game
 ├── Menu ──────┐
 ├── Player ────┼──→ ONE GameSettings object
 └── Audio ─────┘


### Important Parts

private GameSettings()
→ Prevents outside code from creating objects directly.

static GameSettings settings
→ Creates only one object.

static GameSettings& getInstance()
→ Provides access to that single object.


### Interview Answer

"Singleton is a creational design pattern that ensures a class has only
one instance and provides a global access point to that instance."


### Remember

Singleton = One class → One object → Global access.














## Factory Pattern

### Definition

Factory Pattern creates objects without the calling code directly deciding
which concrete class to create.

### Simple Explanation

Instead of creating objects directly:

Car c;
Bike b;

We ask a Factory to create the object:

You → Factory → Car/Bike


### Example

class Vehicle {
public:
    virtual void drive() = 0;
};

class Car : public Vehicle {
public:
    void drive() override {
        cout << "Driving Car";
    }
};

class Bike : public Vehicle {
public:
    void drive() override {
        cout << "Riding Bike";
    }
};


### Factory

class VehicleFactory {
public:
    static Vehicle* create(string type) {

        if (type == "car")
            return new Car();

        if (type == "bike")
            return new Bike();

        return nullptr;
    }
};


### Usage

Vehicle* v = VehicleFactory::create("car");
v->drive();


### Why Use Factory?

Without Factory:

Main code
 ├── knows Car
 ├── knows Bike
 └── creates them directly


With Factory:

Main code
      ↓
   Factory
    ↙   ↘
  Car   Bike


The object creation logic is kept in one place.


### Interview Answer

"Factory is a creational design pattern that centralizes object creation
and allows the client to create objects without directly depending on
their concrete classes."


### Remember

Factory = Object creation is handled by a separate Factory.

















## Strategy Pattern

### Definition
Allows us to choose different ways of performing an operation without
changing the main class.

### Simple Explanation
Different behavior → separate classes → choose one at runtime.

Example: Payment
Payment → UPI / CreditCard / PayPal

### Example

class PaymentStrategy {
public:
    virtual void pay() = 0;
};

class UPI : public PaymentStrategy {
public:
    void pay() override {
        cout << "UPI Payment";
    }
};

class CreditCard : public PaymentStrategy {
public:
    void pay() override {
        cout << "Card Payment";
    }
};

class Payment {
    PaymentStrategy* strategy;

public:
    Payment(PaymentStrategy* s) : strategy(s) {}

    void pay() {
        strategy->pay();
    }
};

### Usage

UPI upi;
Payment p(&upi);
p.pay();

### Why use it?
Avoid putting multiple behaviors inside one large class.

### Interview Answer
"Strategy separates different behaviors into separate classes and allows
us to choose the required behavior at runtime."

### Remember
Strategy = Different ways → Separate classes → Choose one.














## Observer Pattern

### Definition
Observer Pattern allows multiple objects to automatically receive updates
when another object's state changes.

### Simple Explanation
One object changes → automatically notifies many objects.

Example:
YouTube Channel → Subscribers

Channel = Subject
Subscribers = Observers

### Example

class Observer {
public:
    virtual void update() = 0;
};

class Subscriber : public Observer {
public:
    void update() override {
        cout << "New video uploaded!";
    }
};

class YouTubeChannel {
    vector<Observer*> subscribers;

public:
    void subscribe(Observer* o) {
        subscribers.push_back(o);
    }

    void uploadVideo() {
        for (auto o : subscribers)
            o->update();
    }
};

### Why use it?
When one object's change needs to automatically notify multiple objects.

### Interview Answer
"Observer is a behavioral design pattern where multiple objects subscribe
to a subject and are automatically notified when its state changes."

### Remember
Observer = One object changes → Notify many objects.














## Builder Pattern

### Definition
Builder Pattern creates complex objects step-by-step.

### Simple Explanation
Complex object → Set required/optional values → Build object.

Example:
Computer → CPU → RAM → Storage → GPU → Computer

### Example

class Computer {
public:
    string cpu;
    int ram;
    int storage;
};

class ComputerBuilder {
    Computer pc;

public:
    ComputerBuilder& setCPU(string c) {
        pc.cpu = c;
        return *this;
    }

    ComputerBuilder& setRAM(int r) {
        pc.ram = r;
        return *this;
    }

    ComputerBuilder& setStorage(int s) {
        pc.storage = s;
        return *this;
    }

    Computer build() {
        return pc;
    }
};

### Usage

Computer pc = ComputerBuilder()
                .setCPU("i5")
                .setRAM(16)
                .setStorage(512)
                .build();

### Why use it?
Avoids large constructors and makes object creation clean and readable.

### Interview Answer
"Builder is a creational design pattern used to construct complex objects
step-by-step, especially when they have many optional parameters."

### Remember
Builder = Complex object → Build step-by-step.














## Adapter Pattern

### Definition
Adapter Pattern allows incompatible classes/interfaces to work together.

### Simple Explanation
Existing class has a different interface → Adapter converts it
to the interface our system expects.

Example:
Phone → Charger Adapter → Wall Socket

### Example

class Payment {
public:
    virtual void pay() = 0;
};

class OldPayment {
public:
    void makePayment() {
        cout << "Old payment";
    }
};

class PaymentAdapter : public Payment {
    OldPayment oldPayment;

public:
    void pay() override {
        oldPayment.makePayment();
    }
};

### Usage

Payment* p = new PaymentAdapter();
p->pay();

### Why use it?
To use existing/third-party code whose interface doesn't match
our system, without modifying that code.

### Interview Answer
"Adapter is a structural design pattern that converts an existing
interface into the interface expected by the client."

### Remember
Adapter = Incompatible interface → Adapter → Compatible interface.

### Key Takeaway:
- **Coupling**: How much one part of a program depends on another part. 
  - **High Coupling**: Methods depend on implementation details.
  - **Low Coupling**: Methods depend on abstractions.
- **Dependency**: How one class relies on another class.
  - **High Dependency**: Directly uses implementation details.
  - **Low Dependency**: Uses abstractions.

By keeping coupling and dependency low, you make your code more modular and easier to maintain.


These rules will help you design more modular and maintainable classes.

class AbstractClass {

// ============================================================
//                 OOPS - ALL CONCEPTS IN ONE FILE
// ============================================================
//
// 4 MAIN PILLARS OF OOPS:
//
// 1. Encapsulation
// 2. Inheritance
// 3. Abstraction
// 4. Polymorphism
//
// Other concepts used below:
// Class, Object, Data Member, Member Function,
// Constructor, private, protected, public,
// virtual, pure virtual function, override, etc.
// ============================================================



// ============================================================
// 1. ENCAPSULATION
// ============================================================
//
// Encapsulation = wrapping DATA + FUNCTIONS together
// inside a class and controlling access to the data.
//
// DATA MEMBER:
//     balance → stores data
//
// MEMBER FUNCTIONS:
//     deposit()    → works on balance
//     getBalance() → gives us balance
// ============================================================

class BankAccount
{
private:

    // DATA MEMBER
    // balance stores the account's data.
    //
    // private means:
    // Only BankAccount itself can directly access balance.
    double balance;


public:

    // CONSTRUCTOR
    //
    // A constructor is automatically called when
    // an object is created.
    BankAccount(double amount)
    {
        balance = amount;
    }


    // MEMBER FUNCTION
    //
    // deposit() works on the data member 'balance'.
    void deposit(double amount)
    {
        balance += amount;
    }


    // MEMBER FUNCTION
    //
    // getBalance() returns the value of balance.
    double getBalance()
    {
        return balance;
    }
};



// ============================================================
// 2. INHERITANCE
// ============================================================
//
// Inheritance = one class gets properties/functions
// from another class.
//
// Animal = BASE / PARENT class
// Dog    = DERIVED / CHILD class
//
//        Animal
//           ↑
//           |
//          Dog
// ============================================================

class Animal
{
protected:

    // DATA MEMBER
    //
    // protected means:
    // 1. Animal can access it
    // 2. Child classes can access it
    // 3. Outside code cannot directly access it
    string name;


public:

    // CONSTRUCTOR
    Animal(string n)
    {
        name = n;
    }


    // MEMBER FUNCTION
    void eat()
    {
        cout << name << " is eating" << endl;
    }
};



// Dog INHERITS from Animal.
//
// ':' means inheritance.
//
// public Animal means:
// Dog publicly inherits from Animal.
class Dog : public Animal
{
public:

    // DOG CONSTRUCTOR
    //
    // : Animal(n)
    // calls the constructor of the parent class.
    Dog(string n) : Animal(n)
    {
    }


    // MEMBER FUNCTION belonging to Dog
    void bark()
    {
        // name belongs to Animal.
        //
        // Dog can access it because name is PROTECTED.
        cout << name << " is barking" << endl;
    }
};



// ============================================================
// 3. ABSTRACTION
// ============================================================
//
// Abstraction = showing WHAT something should do,
// while hiding HOW it is implemented.
//
// Shape says:
// "Every shape must have area()."
//
// But Shape doesn't tell us HOW to calculate the area.
//
// Circle and Rectangle provide their own implementation.
// ============================================================


// ABSTRACT CLASS
class Shape
{
public:

    // PURE VIRTUAL FUNCTION
    //
    // = 0 means this function has no implementation here.
    //
    // Child classes MUST implement area().
    virtual void area() = 0;
};



// Circle INHERITS from Shape.
class Circle : public Shape
{
private:

    // DATA MEMBER
    double radius;


public:

    // CONSTRUCTOR
    Circle(double r)
    {
        radius = r;
    }


    // OVERRIDE
    //
    // Circle provides its own implementation of
    // Shape's pure virtual area() function.
    void area() override
    {
        cout << "Circle area = "
             << 3.14 * radius * radius
             << endl;
    }
};



// Rectangle INHERITS from Shape.
class Rectangle : public Shape
{
private:

    // DATA MEMBERS
    double length;
    double width;


public:

    // CONSTRUCTOR
    Rectangle(double l, double w)
    {
        length = l;
        width = w;
    }


    // OVERRIDE
    //
    // Rectangle provides its own implementation
    // of area().
    void area() override
    {
        cout << "Rectangle area = "
             << length * width
             << endl;
    }
};



// ============================================================
// 4. POLYMORPHISM
// ============================================================
//
// Polymorphism = ONE INTERFACE, MANY FORMS.
//
// Same function:
//
//     sound()
//
// But different classes provide different behavior.
//
// Dog  → Woof
// Cat  → Meow
// ============================================================


class Animal2
{
public:

    // VIRTUAL FUNCTION
    //
    // virtual allows C++ to choose the correct
    // child function at RUNTIME.
    virtual void sound()
    {
        cout << "Animal makes a sound" << endl;
    }


    // VIRTUAL DESTRUCTOR
    //
    // Good practice when using inheritance
    // and deleting objects through a base pointer.
    virtual ~Animal2()
    {
    }
};



// Dog2 INHERITS from Animal2.
class Dog2 : public Animal2
{
public:

    // OVERRIDING sound()
    //
    // Dog has its own version of sound().
    void sound() override
    {
        cout << "Dog says: Woof!" << endl;
    }
};



// Cat2 INHERITS from Animal2.
class Cat2 : public Animal2
{
public:

    // OVERRIDING sound()
    //
    // Cat has its own version of sound().
    void sound() override
    {
        cout << "Cat says: Meow!" << endl;
    }
};



// ============================================================
//                       MAIN FUNCTION
// ============================================================

int main()
{

    // ========================================================
    // ENCAPSULATION DEMO
    // ========================================================

    cout << "===== ENCAPSULATION =====" << endl;


    // OBJECT
    //
    // account is an OBJECT of BankAccount class.
    //
    // Class  → BankAccount
    // Object → account
    BankAccount account(1000);


    // We CANNOT do:
    //
    // account.balance = 5000;
    //
    // ❌ ERROR
    //
    // Because balance is PRIVATE.


    // Instead, we use the public member function.
    account.deposit(500);


    // getBalance() gives us the private data.
    cout << "Balance = "
         << account.getBalance()
         << endl;



    // ========================================================
    // INHERITANCE DEMO
    // ========================================================

    cout << "\n===== INHERITANCE =====" << endl;


    // Creating a Dog OBJECT.
    Dog dog("Bruno");


    // eat() belongs to Animal.
    //
    // Dog can use it because Dog inherits from Animal.
    dog.eat();


    // bark() belongs to Dog.
    dog.bark();



    // ========================================================
    // ABSTRACTION DEMO
    // ========================================================

    cout << "\n===== ABSTRACTION =====" << endl;


    // We CANNOT create an object of Shape:
    //
    // Shape shape;
    //
    // ❌ ERROR
    //
    // Because Shape is an ABSTRACT CLASS.


    // Shape pointer pointing to Circle object.
    Shape* shape1 = new Circle(5);


    // Shape pointer pointing to Rectangle object.
    Shape* shape2 = new Rectangle(10, 4);


    // We don't need to know how Circle calculates area.
    // We simply call area().
    shape1->area();


    // We don't need to know how Rectangle calculates area.
    // We simply call area().
    shape2->area();


    // Free dynamically allocated memory.
    delete shape1;
    delete shape2;



    // ========================================================
    // POLYMORPHISM DEMO
    // ========================================================

    cout << "\n===== POLYMORPHISM =====" << endl;


    // BASE CLASS POINTER
    Animal2* animal;


    // animal points to a Dog2 object.
    animal = new Dog2();


    // Same function call:
    //
    // sound()
    //
    // But Dog2's sound() executes.
    //
    // Output:
    // Dog says: Woof!
    animal->sound();


    // Delete Dog2 object.
    delete animal;


    // Now the SAME pointer points to Cat2.
    animal = new Cat2();


    // Same function call:
    //
    // sound()
    //
    // But now Cat2's sound() executes.
    //
    // Output:
    // Cat says: Meow!
    animal->sound();


    // Delete Cat2 object.
    delete animal;


    // Program finished successfully.
    return 0;
}
